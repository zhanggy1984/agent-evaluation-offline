# 新 Agent 接入指南（manifest v2 + 标准契约）

> **平台定标准，agent 遵守适配**。本平台对 agent 零特判：发现、校验、评测只认标准契约信号，
> 任何新 agent（内部自研或第三方）满足本文档即可接入评测。
>
> 权威来源：本文档是对平台校验代码的说明，**以代码为准**——
> `backend/app/core/probe.py`（契约探测判定）、`backend/app/core/contracts_v2.py`（v2 manifest 解析/校验）。
> 4 家已接入样例：`customer-service`（SSE）、`smart-procurement`（SSE 双接口）、
> `good-question`（SSE + field_map）、`contract-check`（同步 JSON + 文件上传），完整 manifest 见
> `backend/app/seed_data.py::MANIFEST_SNAPSHOTS`。

## 1. 接入总览

新 agent 接入评测只需三步：

```
① 实现标准端点  GET /api/contracts  返回 v2 manifest（见 §2）
② 契约达标      SSE §5.1 或 同步 §5.2（见 §3 / §4）
③ 平台注册      填 URL → discover → 确认 adapter → 配置凭证 → 冒烟 → 用例骨架 → 落库（见 §6，或 Q7 前端 wizard）
```

- **接入标准由平台指定**：manifest 的 contract 段声明「平台该怎么驱动我」（前置步骤、请求模板、占位符），
  adapter_config 由平台服务端权威生成，agent 只需把 manifest 写好。
- **快速自测**：`python scripts/verify_agent.py --agent-url <你的地址>` 即可离线校验 manifest 是否达标（见 §7），
  无需先接平台。

## 2. v2 manifest 写法

### 2.1 顶层结构

```jsonc
{
  "agent": "my-agent",              // 推荐与平台注册名一致
  "contract_version": "2.0",        // v2 标志（契约段存在即视为 v2，本字段用于展示）
  "interfaces": [                   // 全部对外接口清单（含辅助接口）
    { "name": "chat", "path": "/api/chat", "method": "POST",
      "contract_type": "sse", "llm": true, "description": "对话评测接口" }
  ],
  "scenes": [                       // 业务场景清单（可选，Q5 用例骨架按场景生成用例）
    { "tag": "greeting", "description": "问候与闲聊" }
  ],
  "contract": {                     // 契约段：平台该怎么驱动我（v2 核心）
    "type": "sse", "timeout": 120,
    "prepare": [],                  // 前置步骤（可选）
    "request": { "path": "/api/chat", "method": "POST",
                 "body": { "content": "{{input.content}}" } }
  }
}
```

### 2.2 interfaces（接口清单）

| 字段 | 必选 | 说明 |
|---|---|---|
| `name` | ✅ | 接口名，唯一 |
| `path` | ✅ | 接口路径（可含 prepare 产物占位，如 `/api/sessions/{{prepare.session.id}}/messages`） |
| `method` | ✅ | HTTP 方法 |
| `contract_type` | ✅ | `sse` 或 `sync`，须与 contract.type 一致 |
| `llm` | ✅ | `true` = 评测接口（跑分、生成用例），`false` = 辅助接口（prepare 步骤用） |
| `description` | ⬜ | 说明，供平台展示 |

> 一个 agent 可有多个 `llm=true` 接口（如 smart-procurement 的 `chat` + `score`），平台会逐一评测。

### 2.3 scenes（业务场景）

```json
{ "tag": "greeting", "description": "问候与闲聊" }
```

- `tag` 是场景标签（唯一）；平台用它给用例打标签、按场景生成用例骨架（Q5）。
- 平台 `POST /agents/{id}/scenes` 可写读场景清单；`POST /cases/{id}/scenes` 给用例打标签。

### 2.4 contract（契约段：平台该怎么驱动我）

```jsonc
"contract": {
  "type": "sse", "timeout": 120,
  "prepare": [
    {   // 前置步骤：鉴权 / 建会话 / 上传文件，可多个，步骤间通过 extract 产物引用
      "name": "login", "method": "POST", "path": "/api/v1/auth/login",
      "body": { "username": "{{auth.username}}", "password": "{{auth.password}}" },
      "extract": { "token": "access_token" }      // key 名自定义 → 响应字段路径
    },
    {   // 引用上一步产物：{{prepare.login.token}}
      "name": "session", "method": "POST", "path": "/api/v1/sessions",
      "headers": { "Authorization": "Bearer {{prepare.login.token}}" },
      "extract": { "id": "session_id" }            // 响应是 {session_id} 时映射到 id
    }
  ],
  "request": {
    "path": "/api/v1/sessions/{{prepare.session.id}}/messages", "method": "POST",
    "headers": { "Authorization": "Bearer {{prepare.login.token}}",
                 "Content-Type": "application/json" },
    "body": { "content": "{{input.content}}" }
  }
}
```

#### prepare 步骤（可选，无则省）

- **普通步骤**：`method/path/headers/body/files` + `extract`。`extract` 从响应中按字段路径取值，
  供后续步骤或 request 引用（`{{prepare.<步骤名>.<key>}}`）。
- **poll 轮询步骤**（等待任务到达可消费状态）：

  ```jsonc
  { "name": "wait_done", "poll": {
      "path": "/api/tasks/{{prepare.upload.task_id}}",     // 轮询目标
      "until": { "status": ["WAITING_REVIEW", "SUCCESS", "FAILED", "CANCELLED"] },
      "interval": 2, "timeout": 300 } }
  ```

  轮询直到响应 `status` 命中 `until` 列表（contract-check 决策 #41：到 `WAITING_REVIEW` 即可取数，不触发业务 review）。

#### request（最终评测请求）

- `path/method/headers/body`，可引用 `{{prepare.*}}` 与 `{{input.*}}`。

#### sse.field_map（可选，事件名映射）

- 当 agent 终答事件名与平台统一口径不一致时映射。例：good-question 终答事件是 `token` 而非 `answer`：

  ```json
  "sse": { "field_map": { "token": "answer" } }
  ```

#### 文件型上传（contract-check 样例）

```jsonc
"prepare": [
  { "name": "upload", "method": "POST", "path": "/api/files/upload",
    "files": { "file": "{{input.file_path}}" },          // 平台 uploads 内样例文件路径
    "extract": { "task_id": "task_id" } }
]
```

### 2.5 占位符三域

| 域 | 来源 | 用途 | 示例 |
|---|---|---|---|
| `{{input.*}}` | 平台用例输入（`case.input`） | 请求 body / 文件路径 | `{{input.content}}`、`{{input.file_path}}` |
| `{{auth.*}}` | 平台注册 agent 时配置的 secrets | 凭证 | `{{auth.username}}`、`{{auth.password}}` |
| `{{prepare.X.f}}` | 前序 prepare 步骤 `extract` 的产物 | 步骤间传参 | `{{prepare.login.token}}` |

平台从 `{{input.*}}` 汇总出**接口需要的用例输入字段域**（`input_fields`，嵌套路径收全路径），
供 Q5 用例骨架与用例校验使用。

### 2.6 校验规则（Q1 硬错误闸门）

平台 `build_adapter_config` 对 manifest 做占位符引用校验，**硬错误直接拒绝生成 adapter**（防坏 adapter 入库）：

| 校验 | 结果 |
|---|---|
| `{{prepare.X.f}}` 引用不存在的 prepare 步骤 X | 硬错误 |
| X 的 `extract` 未声明字段 f | 硬错误 |
| `{{prepare.X}}` 缺字段名 | 硬错误 |
| 未知占位符域（`{{foo.bar}}`） | 硬错误 |
| 无 `llm=true` 接口 | 硬错误 |
| extract 声明了但无人引用 | 软警告（不阻断） |

> 校验覆盖 request + prepare + sse 全部渲染域（sse 域曾漏扫，hook 抓 bug 后已补）。

## 3. SSE 契约 §5.1 达标指南

### 3.1 平台判定口径（probe.py，以代码为准）

```python
SSE_MANDATORY = ("usage", "done")   # 必选事件；其余可选
```

- **必选事件**：`usage`、`done`。缺任一 → 探测报「未收到 usage/done 事件（§5.1 必选）」。
- **usage 合法性**：`prompt_tokens`/`completion_tokens`/`total_tokens` 三分量存在且非负（`_usage_ok`）。
- 事件类型全集：`meta`/`stage`/`reasoning`/`tool_call`/`answer`/`usage`/`done`/`error`。
- 建议顺序：`meta` 首个 → `reasoning*/token*` → `[tool_call → sources]?` → `reasoning*/token*` → `usage` → `done`。

### 3.2 SSE 帧格式

标准 SSE（`text/event-stream`），一行一字段：

```
event: meta
id: 1
data: {"agent": "my-agent", "model": "gpt-4o", "interface": "chat",
       "contract_version": "2.0", "git_sha": "abc123", "knowledge_version": "v3",
       "ts": 1725000000000}

event: token
id: 2
data: {"content": "你好", "delta": "你好", "ts": 1725000000001}

event: usage
id: 8
data: {"prompt_tokens": 120, "completion_tokens": 45, "total_tokens": 165, "ts": 1725000000010}

event: done
id: 9
data: {"ts": 1725000000010}
```

### 3.3 每类事件字段规范

| 事件 | 必带字段 | 说明 |
|---|---|---|
| `meta` | `agent`/`model`/`interface`/`contract_version`/`git_sha`/`knowledge_version`/`ts` | 首事件，元信息；`git_sha`/`knowledge_version` 可空串 |
| `reasoning` / `token` | `content` + `delta` + `ts` | 双字段并存（前端 content 与评测 delta 双消费）；单帧流式时 `content == delta` |
| `tool_call` | `id`/`name`/`args`/`result`/`status`/`ts` | 工具调用回传；`status ∈ {ok, error, rule_override, rule_override_error}`；命中检索后另发 `sources` 事件 |
| `answer` | 终答内容 | 最终答案；事件名不一致时经 `sse.field_map` 映射 |
| `usage` | `prompt_tokens`/`completion_tokens`/`total_tokens` + `ts` | 多轮合并后在 `done` 前发一次即可 |
| `done` | `ts` | 结束标记，最后一个事件 |
| `error` | — | 内部异常；出现会触发探测失败上报 |

### 3.4 反面案例（4 家踩过的坑）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 终答事件名不是 `answer` | 探测 fields 无 answer | `contract.sse.field_map: {"token": "answer"}`（good-question） |
| 缺 `usage` / `done` | 探测报「未收到 usage/done 事件（§5.1 必选）」 | 事件流强制收尾 `usage` → `done` |
| 流式帧缺 `delta` | 前端/评测无法消费增量 | `content` 与 `delta` 双字段并存 |
| 事件不带 `ts` | 时间戳校验失败 / 评测拿不到时序 | 全事件 data 带 `ts`（int） |
| usage 缺三分量之一 | `_usage_ok` 判定非法 | `prompt/completion/total_tokens` 三者齐全非负 |
| 多轮 token 每次发 usage | usage 重复计费口径混乱 | 多轮合并，`done` 前发一次 |

## 4. 同步契约 §5.2

### 4.1 平台判定口径（probe.py，以代码为准）

同步变体（JSON 响应）必选三项：

| 字段 | 判定 | 说明 |
|---|---|---|
| `answer` | 非空 | 最终答案 |
| `usage` | 三分量合法（同 §3.1） | token 计数 |
| `timing` | `start_ts`/`end_ts` 存在 | 耗时区间 |

`contract_type: "sync"`，不验 `done`。

### 4.2 JSON 样例

```json
{
  "answer": "该合同缺失生效日期条款，建议补充。",
  "usage": { "prompt_tokens": 320, "completion_tokens": 88, "total_tokens": 408 },
  "timing": { "start_ts": 1725000000000, "end_ts": 1725000008500 },
  "tool_calls": []
}
```

## 6. 端到端接入流程（平台侧）

| 步骤 | 平台操作 | 对应 API |
|---|---|---|
| 1 | 注册 agent，填 URL（含 manifest 端点） | `POST /agents` |
| 2 | 拉取 manifest，展示接口/场景 + adapter 草案 + 漂移提示 | `POST /agents/{id}/discover` |
| 3 | 确认 manifest → 服务端权威生成 adapter 落库 | `POST /agents/{id}/adapter` |
| 4 | 配置凭证（`{{auth.*}}` 来源） | `PUT /agents/{id}/auth` |
| 5 | 冒烟探测：逐字段验证契约达标 | `POST /agents/{id}/probe` |
| 6 | 生成用例骨架 → 确认落库（每 scene × 每 llm 接口一个 case） | `POST /agents/{id}/skeleton` → `POST /suites` + `POST /suites/{id}/cases` |

Q7 前端 wizard 把这 6 步串成「填 URL → 自动接入」的一体化向导。

## 7. agent 侧自测

### 7.1 静态校验（零依赖，先跑这个）

```bash
python scripts/verify_agent.py --agent-url http://127.0.0.1:8000
```

- 拉取 `GET /api/contracts` → v2 解析 + adapter 派生 → 报告硬错误/软警告/input_fields/requires_auth。
- 硬错误 → 退出码非 0；无硬错误 → 打印「✅ manifest 校验通过」。

### 7.2 平台冒烟（契约真达标，需平台在线）

```bash
python scripts/verify_agent.py --agent-url http://host.docker.internal:8000 \
    --platform-url http://localhost:8180/api \
    --input '{"content": "你好"}' \
    --secrets '{"username": "svc", "password": "xxx"}'
```

- 自动：登录平台 → 注册 agent → 确认 adapter → sync 接口 → 配置凭证 → 冒烟探测 → 断言契约字段达标。
- `--input` 为显式探测输入（Q2 三级来源第 1 级）；文件型 agent 需先放置样例文件到平台 uploads 并传
  `--input '{"file_path": "/app/uploads/xxx.pdf"}'`。
- 复用平台 `POST /agents/{id}/probe`（即平台 `probe_agent` 实现），判定口径与平台完全一致。
