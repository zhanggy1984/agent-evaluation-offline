# 评测平台用户使用指南

> 面向评测平台的使用者（管理员 / 评测员 / 查看者）。本文从"完全不了解这个平台"开始，
> 一步步讲清怎么看、怎么测、怎么看懂结果。全程不需要懂代码。
>
> 如果你的任务是**把一个新的 agent 接进来评测**，请先看 [Agent 接入评测指南](Agent接入评测指南.md)。

---

## 一、这个平台是干什么的

它是一个 **AI Agent 的线下评测平台**：在隔离测试环境里，用固定的一套测试用例，对你的
agent 核心接口发请求，量化打分，并给出"为什么得这个分"的证据。

它回答三类问题：

| 你想知道的 | 平台给出的答案 |
|---|---|
| 答案准不准 | 每个用例的得分、每道题失分在哪（judge 判定理由） |
| 快不快 / 贵不贵 | 首字延迟、端到端耗时（性能）、token 消耗与费用（成本） |
| 改一次代码是变好还是变坏 | 多次评测结果的**趋势**与**版本对比** |

> 评测范围：只评**有 LLM 参与的核心业务接口**（对话、问答、合同审查这类）。注册登录、
> CRUD、健康检查等不评。

---

## 二、登录与账号角色

打开浏览器访问平台地址（部署方会给你，通常是 `http://localhost:8180`），用分配好的账号密码登录。

平台有三种角色，**权限从上到下**：

| 角色 | 能做什么 |
|---|---|
| **管理员（admin）** | 全部功能：新建/编辑 agent、配置中心、用户管理、接入 agent 并落库、跑评测 |
| **评测员（evaluator）** | 触发评测、管理用例与标注、查看/导出结果（比 viewer 多"动手"权限） |
| **查看者（viewer）** | 只读：看板、评测记录、结果明细，不能发起任何操作 |

> 说明：本文中"评测员/管理员"能做的操作，通常"管理员"一定也能做。下文按"你需要什么权限"标注。
> 首次登录如果被要求**修改密码**，改完才能继续。

## 三、先懂这几个词（核心概念）

用"点外卖"打比方：

| 词 | 含义 | 类比 |
|---|---|---|
| **Agent** | 被评测的对象，一个要接入的 AI 服务 | 一家餐厅 |
| **测试集（套件 / Suite）** | 一组打包好的测试用例 | 一份菜单 |
| **用例（Case）** | 一条具体的测试题：输入 + 期望答案 + 断言 | 一道菜 |
| **评测（Run）** | 对某个 agent 跑一次评测（选一个测试集），产生一份结果 | 下一次单 |
| **评测维度** | 从几个角度分别打分：答案质量（事实性/完整性/推理/工具使用）+ 性能 + 成本 | 口味/速度/价格 |
| **门禁** | 一把"过不过线"的尺子：每个 agent 有达标分，低于达标分的维度标红 | 餐厅评分 4.0 及格 |
| **gold 用例** | 标注了"标准答案"的标杆用例，用于衡量绝对水平 | 招牌菜 |
| **留出集（held-out）** | 平时不外泄、只在正式复测时用的用例集，防止"背题" | 考试的隐藏卷 |

**分数怎么来的**：每道题先按**确定性规则**扣分（比如回答里缺了必填字段、JSON 格式不对），
再用 **LLM judge**（一个专门的评分大模型）按六级量表评语义质量，最后按各维度权重合成 0–100 分。
judge 会给**判定理由**——这就是你能看到"为什么扣分"的原因。

## 四、第一次使用：管理员完整流程（15 分钟跑通）

下面是从零到"出第一份评测报告"的完整路径：

```
登录 → 接入 agent → 准备用例 → 触发评测 → 看结果 → 导出报告
```

### 第 1 步 接入 agent

Agent 管理页右上角有 **「快捷接入」** 按钮（管理员可见），点进去跟着向导走：
填你的 agent 地址 → 平台自动识别接口契约 → 确认配置 → 冒烟探测 → 生成用例骨架 → 落库。

> agent 侧怎么实现标准契约、manifest 怎么写，见 [Agent 接入评测指南](Agent接入评测指南.md)。
> 没有的话，也可以手动「新建 Agent」填地址。

### 第 2 步 准备用例

进入 **用例管理** 页：

1. 左侧**选择 agent**；
2. 下方点按钮**新建测试集（套件）**，给个名字（如"客户咨询回归"）；
3. 在套件里**新建用例**：填"输入"（发给 agent 的问题），可选填"期望答案/断言"；
4. 需要的用例都建好后，建议把有标准答案的用例**打标为 gold**（用例列表点「打标」），用于绝对基线对比。

> 接入 agent 时如果走了"快捷接入"，平台已经按它的业务场景自动生成了用例骨架，你只需要补全输入内容。

### 第 3 步 触发评测

回到 **看板** 页，点右上角 **「触发评测」**，弹出窗口里：

| 选项 | 说明 |
|---|---|
| Agent | 选要测的 agent |
| 测试集 | 选要跑的用例集 |
| 版本 | 选填，给这次评测起个版本号（如 `1.2.0`），方便之后对比 |
| 评测类型 | 普通评测 / **留出集复测**（用隐藏用例正式复测） |

点确认，平台开始跑：**先做契约探测**（验证你的 agent 接口协议达标，不达标直接拦截并标失败），
然后逐条用例执行（先重置数据、再发请求、采集回答与性能）、再交给 judge 判分、最后汇总评分。

> 跑评测前请确认你的 agent 服务在线（平台通过 `host.docker.internal` 访问它）。
> 管理员和评测员都能触发。

### 第 4 步 看结果

看板下方「评测记录」里，新 run 会经历 **等待中 → 执行中 → 评分中 → 完成**。点「明细」逐层下钻：
门禁墙 → 用例明细 → 未达标摘要 → **证据回放**（agent 原始回答、思考链、judge 判定理由、工具调用、token 用量）。

### 第 5 步 导出报告

run 明细页有 **导出报告** 按钮，一键导出 PDF 用于留档/汇报。

## 五、看板页（Dashboard）—— 一屏看全

登录后默认进入看板，分几个区块：

### 5.1 门禁墙（每个 agent 一张卡片）

- **均分 / 通过率 / 用例数**：最近一次评测的汇总；没评测过显示"未评测"。
- **黄色"未达标"提示**：有过评测但还有用例未通过的 agent 会标出来。
- 点卡片或"选择 Agent 下钻"，聚焦单个 agent 看接口/场景覆盖与明细。

### 5.2 评测记录（下方表格）

每行是一次 run，含状态、通过/失败用例数。操作：

| 操作 | 权限 | 说明 |
|---|---|---|
| **触发评测** | 评测员/管理员 | 发起新评测（见第 4 步） |
| **明细** | 全部 | 进入 run 详情逐层下钻 |
| **取消** | 评测员/管理员 | 正在跑（等待中/执行中/评分中）时可以取消 |
| **重跑** | 评测员/管理员 | 已经结束的 run 可以一键重跑同一配置 |
| 状态筛选 / 搜索 | 全部 | 按状态（完成/失败/超时…）或 ID/agent 名过滤 |

**run 状态含义**：

| 状态 | 含义 | 要不要管 |
|---|---|---|
| 等待中 | 排队还没开始 | 不用 |
| 执行中 | 正在跑用例 | 不用 |
| 评分中 | 用例跑完，judge 在判分 | 不用 |
| **完成** | 正常结束 | ✅ 可以看结果了 |
| **部分失败** | 有用例因执行/技术错误（如 agent 连接失败、超时）没测成 | ⚠️ 看是哪条用例、为什么失败 |
| **评分失败** | 判分阶段出问题（评分超时等） | ⚠️ 联系管理员 |
| **超时 / 已取消** | 整轮超时 / 被手动取消 | ⚠️ 确认 agent 在线后重跑 |

### 5.3 性能 / 成本 / 覆盖

- **性能**：接口级首字延迟（TTFT）、端到端耗时，P50/P95 统计——慢在哪一档肉眼可见。
- **成本**：按真实 token 用量 × 单价表算出的费用；**模型单价**可在此维护（元/百万 token）。
- **覆盖**：接口覆盖（哪些接口被测过）+ 场景覆盖（哪些业务场景有用例），"未配置"即缺口。

### 5.4 评测趋势 / 版本对比

- **评测趋势**：多次评测的得分走势——改造前后一目了然。
- **版本对比**：选两次 run（Run A vs Run B）对比，看这次改动哪里变好哪里变差。

## 六、Agent 管理页（Agents）

**新建 Agent**（管理员）：填
- **名称**
- **地址**（`http://host:port`，平台会校验它是否在白名单/内网网段内）
- 版本号、负责人（可选）

**详情**（点「详情」或「编辑」进入）：
- **接口**：列出该 agent 的全部接口。可「新增接口」「编辑」；每个接口可配置
  **权重**（各评测维度的权重）与**达标分**（门禁线，低于此分的维度标红）。
- **契约发现**：读取 agent 声明的接口契约并展示；「同步」把契约正式落到配置里。
  （这是"快捷接入"向导背后的手动操作，一般走向导即可。）
- **变更历史**：agent 配置每次改动都有留痕，可追溯。

**禁用 / 启用**：禁用后该 agent 不再参与评测。

> 页面右上角「快捷接入」是推荐入口——手把手完成 发现 → 确认契约 → 凭证 → 冒烟 → 用例骨架 全流程。

## 七、用例管理页（Cases）

左侧选 agent，右侧两个页签：

### 7.1 用例管理

- **测试集（套件）**：新建 / 编辑 / 删除；套件就是一组用例的集合。
- **用例**：新建 / 编辑 / 删除。用例是核心资产：
  - **输入**：发给 agent 的问题（文本），按 agent 需要的字段填。
  - **期望答案 / 断言**：选填。有期望答案的用例，judge 会以它为"事实参考"判分。
  - **打标**：给用例打标签——`gold`（标杆用例）、`留出`（隐藏复测集）、业务**场景**标签。
  - **标注**：对某次评测结果追加人工评注（比如"这条用例本身有问题，重写"）。
  - **作废**：无效用例标作废，不再计入评测。

### 7.2 标注待办

列出需要人工复核的用例（按 agent 筛选）——评测后核对 judge 打分是否合理时用。

## 八、配置中心（Config）

平台级参数列表，管理员可改。每项含：key、当前值、默认值（填 `null` 回到默认）。
常见项：

| 配置 | 作用 |
|---|---|
| judge LLM 地址 / 模型 | 判分大模型指向（密钥走环境变量） |
| judge 重复判分次数 | 同一题判几次取多数决（默认 3），越多越稳、越贵 |
| judge 并发 / 超时 | 判分的并发度与单次超时 |
| 单用例超时 / 整 run 超时 | 评测执行时限 |
| judge 出站白名单 | 允许 judge 访问的 LLM 域名（安全） |

> 配置多为**热生效**（改完即时生效），部分需要重启。界面会标明。

---

## 九、用户管理页（Users）

管理员维护平台账号：

- **新建用户**：填用户名、选角色（管理员/评测员/查看者）、设初始密码。
- **重置密码**：用户忘记密码时重置。
- **禁用**：停用账号（不能禁自己）。

> 安全提示：登录有防爆破锁定机制，连续输错会临时锁号，等一段时间或用管理员重置。

## 十、结果解读（看懂一份评测）

### 10.1 总览

- **agent 均分**：所有用例的平均分（0–100）。
- **通过率**：达标用例占比。
- **各维度分**：事实性 / 完整性 / 推理 / 工具使用 / 性能 / 成本，分别打分。
  低于该接口达标分的维度会标红——这就是你要修的方向。

### 10.2 逐层下钻（定位问题）

```
L0 门禁墙        agent 汇总：均分 / 通过率 / 用例数
L3 用例明细      每条用例得分 + 各维度分
L3.5 未达标摘要  未达标的用例 + 判定理由汇总
L4 证据回放      agent 原始回答 / 思考链 / judge 判定理由 / 断言详情 / 工具调用 / token 用量
```

> 直接看 L4 证据回放，往往不用复现现场就能知道 agent 错在哪——比如 judge 理由写明
> "回答编造了参考依据中不存在的事实"，你就能回灌 agent 修。

### 10.3 一个 run 的成败判断

- **完成** = 正常测完（不代表都通过；通过不通过看分数与门禁）。
- **部分失败** = 有技术性失败（连接失败、超时、判分失败），**与 agent 答得好不好无关**。
  先看失败原因：是 agent 服务没起来、接口超时，还是用例本身问题。

## 十一、常见问题

| 问题 | 处理 |
|---|---|
| 登录被锁 | 等锁定窗口过，或让管理员重置密码 |
| 触发评测后 run 立刻"部分失败" | 大概率**契约探测未通过**（agent 接口协议不达标）或 agent 服务不在线；看明细里的失败原因 |
| 有接口一直"未配置" | 去 Agent 详情给该接口配权重与达标分，或在快捷接入里确认接口已同步 |
| run 显示"完成"但有黄色"未达标" | 语义如此：完成=测完了；未达标=有题得分低于达标分。看未达标摘要定位 |
| 某维度分低但不知道为啥 | 看 L4 证据回放里的 judge 判定理由 |
| 想确认改造是否变好 | 用「版本对比」选改造前后两次 run |
| 报告要留档 | run 明细页「导出报告」，PDF 带水印 |
